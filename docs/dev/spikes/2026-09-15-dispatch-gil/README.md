# Spike: composition model, Variant dispatch, GIL release

Date: 2026-09-15. Toolchain: Mojo 1.0.0 stable (`.venv/bin/mojo`), x86_64 Linux, 16 threads.

## Question

Which composition model should mdsp use?

- A: Python chains Mojo primitives that each process a whole buffer.
- B: each graph is compiled Mojo, JIT-built via `mojo.importer` (mmmaudio model).
- C: a runtime graph engine in Mojo; Python builds the graph, one Mojo call per block.

Decision: start with A, evolve to C. Kernels expose both `tick` and `process` so C reuses them.

## Files

| File | Measures |
|-|-|
| `onepole_ext.mojo`, `pkg/dsp.mojo`, `bench.py` | zero-copy numpy -> Mojo, per-call overhead |
| `chain.mojo` | compile-time `Chain[A: Processor, B: Processor]` |
| `dispatch_handwritten.mojo` | static vs `Variant` dispatch, block vs per-sample scheduling |
| `dispatch_generated.mojo` | same, dispatch generated by `comptime for` over `Variant[*Ts]` |
| `gil.py` | whether a Mojo extension call holds the GIL |
| `gil2.mojo`, `gil2.py` | releasing the GIL with `PyEval_SaveThread` |

Build: `mojo build --emit shared-lib -I . onepole_ext.mojo -o onepole_ext.so`, or `mojo build X.mojo -o X && ./X` for executables. Python scripts need numpy: `uv run --with numpy python bench.py`.

## Results

Python boundary (`bench.py`):

- One-pole over 480k samples in one call: 202 M samples/s.
- Per-call overhead: 1.9 us.
- First build of an extension module: about 5 s.

Compile-time chain (`chain.mojo`): 3 stages at 575 M samples/s.

Dispatch, 17-node graph `Saw -> (OnePole -> Gain) x 8`, M samples/s, outputs bit-identical across strategies:

| Strategy | block 1 | 16 | 64 | 512 |
|-|-|-|-|-|
| static, inlined per-sample `tick` | 171 | 176 | 181 | 183 |
| static, per-node block `process` | 26 | 112 | 70 | 66 |
| Variant per node per block, hand-written | 24 | 105 | 68 | 65 |
| Variant per node per block, generated | 25 | 87 | 62 | 59 |
| Variant per node per sample | 89 | 88 | 90 | 90 |

- Variant dispatch costs 2-7% over static block processing. Generated dispatch costs another 10-20%; cause not investigated.
- Scheduling dominates. Chained recursive filters run faster interleaved per sample than per block. Probable cause, not verified with perf counters: each filter's loop-carried dependency serialises block mode, while interleaving lets out-of-order execution overlap stages.
- The graph has no vectorisable nodes. Graphs dominated by SIMD-friendly nodes should favour block mode.

GIL:

- `PythonModuleBuilder` functions hold the GIL: 4 threads give 1.01x.
- Wrapping the kernel loop in `Python().cpython().PyEval_SaveThread()` / `PyEval_RestoreThread()` gives 3.25x on 4 threads. No `PythonObject` may be touched while released.

## Mojo 1.0 stable notes

- `@inline(.always)` does not parse; use `@always_inline`. The bundled skills target nightly.
- Types passed to `add_type` must conform to `Writable`.
- A generic field of trait type needs the trait to refine `Deinitable`.
- Pointer from address: `Pointer[Float32, MutAnyOrigin](unsafe_from_address=addr)`.
- A pointer returned by `List.unsafe_ptr()` has a tracked origin and does not convert to `MutAnyOrigin`; pass addresses as `Int`.
- Variadic pack length: `len(Ts)`.
- The first dispatch spike used `sin()` in the source node, which capped every strategy at ~100 M samples/s and hid dispatch cost; it was discarded.
